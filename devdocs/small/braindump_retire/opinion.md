# Braindump の役割完了時における退役・削除フローに関する課題と提言

## 1. 背景と課題

現在、`nctl` における Braindump の削除（`nctl braindump purge`）は、対象ドキュメントのステータスが `superseded`（置き換え済み）になっている場合のみ許可される仕様となっている。

これにより、すでにノードの退役や単発のタスクが完了し、内容が現状と乖離して不要になった Braindump を整理・削除したい場合でも、以下の問題が発生している：

1. **無駄な工数とダミーデータの発生**:
   単に不要になっただけの Braindump を削除するために、実質的な意味を持たない「まとめ」や「ダミー」の新 Braindump をわざわざ作成し、`supersede` を経由させてから `purge` する必要があり、運用上のオーバーヘッドが大きい。
2. **概念の混同**:
   「別の要望へ引き継がれた・更新された（Superseded）」と「役割を終えて解決・消滅した（Completed / Obsolete）」は本来異なる概念であるが、全てを `supersede` 経由に強制することでモデル上の歪みが生じている。
3. **安全策（ガードレール）の裏返し**:
   `active` 状態からの直接削除を禁止しているのは「重要なアクティブ要件を誤って消去しないための保護」として機能しているが、安全策が原因で実運用上の柔軟性が阻害されている。

---

## 2. 提言（解決案）

上記の課題を解決し、クリーンで安全な運用を実現するために以下のいずれか（または両方）の改善を提言する。

### 提言A: ステータスに `completed` / `archived` を導入し、直接のステータス遷移を許可する（推奨）

Braindump のライフサイクルに「完了・役目終了」を表す状態を追加し、直接遷移できるようにする。

- **仕様案**:
  - `nctl braindump archive <ID>` または `nctl braindump complete <ID>` コマンドを新設。
  - ダミーの Braindump を作成することなく、`active` から直接 `completed` または `archived` に移行可能とする。
  - `completed` / `archived` になったドキュメントは `purge` コマンドで物理削除を可能にする（または履歴として保持する）。
- **メリット**:
  - 「更新」と「完了」の概念が正しく分離され、ダミーデータ作成の手間が不要になる。
  - `active` の直接削除を防ぐガードレールが維持され、安全性も担保できる。

---

### 提言B: `purge` コマンドに明示的な直接パージオプション（`--force` 等）を追加する

アクティブな Braindump であっても、明示的な意図を示すオプションが指定された場合は直接パージを認める。

- **仕様案**:
  - `nctl braindump purge <ID> --force --yes`
  - `--force` フラグが付与された場合のみ、`status=active` であっても API / CLI での直接パージを許可する。
- **メリット**:
  - 最も実装および運用コマンドがシンプルであり、1回のコマンドで完結する。
  - `--force` と `--yes` の両方を要求することで、誤操作や AI 代理による意図しない削除を防ぐ保護機能は維持される。

---

## 3. まとめ

既存の「すべてを `supersede` 経由で消す」フローは、過去の要望履歴の保全という意味では厳密であるが、単発タスクやノード削除等の実運用においては過剰な手続きとなっている。

要望の解決・終了を直接表現できる `complete` / `archive` ステータスの導入（提言A）、または過失を防ぐフラグ付きの直接パージ（提言B）を導入することで、決定性と安全性を損なわずに開発・運用効率を向上させることができる。
